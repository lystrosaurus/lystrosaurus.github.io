# 智识花园 · 书库 → 微信小程序 功能分析与实现方案

> 把静态站点 `lystrosaurus.github.io` 的「书籍模块」迁移为供个人阅读的微信小程序。
> 配套代码已落地在仓库 `miniprogram/` 目录，本文件是其功能分析与实现说明。

---

## 1. 现有书籍模块分析

### 1.1 代码位置与组成

| 文件 | 职责 |
| --- | --- |
| `src/data/books.ts` | **单一真相源**：书名、作者、分类、年份、摘要、核心命题、知识点、可行动洞察、金句、关联书目、榨取状态 |
| `src/data/books.types.ts` | 全部 TS 接口（`Book` / `Category` / `KnowledgePoint` / `Synthesis` …） |
| `src/utils/garden.ts` | 配色、分级色、内联 markdown 渲染等纯函数 |
| `src/pages/books/index.astro` | 书库列表页（统计、分类/状态筛选、网格） |
| `src/pages/books/[slug].astro` | 书籍详情页（摘要/核心命题/知识点分级/可行动/金句/关联书目） |
| `src/components/BookCard.astro` | 复用的书籍卡片 |
| `src/components/BottomNav.astro` | 移动端底部导航，「书库」为主入口之一 |
| `src/pages/search.astro` | 全站搜索，书籍以 `type:'book'` 纳入索引 |
| `src/pages/syntheses.astro` | 跨书复盘，通过 `bookIds` 反查书目 |

### 1.2 数据结构（核心字段）

```
Book {
  id, title, author, category(CategoryId), year, accent,
  summary, coreThesis,
  knowledgePoints[] { concept, detail, level: 基础|进阶|心法 },
  actionable[], quotes[], relatedBookIds[],
  extracted: boolean, extractedAt
}
Category { id, name, icon(emoji), desc, accent }
Synthesis { id, title, theme, bookIds[], summary, points[] }
```

当前数据规模：**21 本书 / 8 个分类 / 2 条跨书复盘**。

### 1.3 ⚠️ 关键发现：现有模块是「知识萃取系统」，不是「全文阅读器」

数据里**没有书籍正文全文**。它存的是每本书被 Agent 萃取后的结构化笔记：摘要、核心命题、按「基础/进阶/心法」三级组织的知识点、可行动洞察、金句，以及书目间的关联网络。

因此，站点上所谓的「阅读体验」= 浏览这本结构化的萃取内容。小程序必须**忠于这一数据形态**来设计「阅读界面」，而不是凭空造一个全文阅读器（那会与「数据需与站点保持一致」矛盾，且会丢失单一真相源）。

**结论：小程序的「阅读」= 把每本书的结构化萃取内容渲染为一条可滚动的阅读流**，而非小说式正文。阅读进度、书签都落在这条流的「块（block）」粒度上。

## 3. 数据同步方案（单一真相源 + 双端一致）

**原则：不复制数据，只转换形态。** 站点 `src/data/books.ts` 仍是唯一真相源。

```
src/data/books.ts ──(scripts/gen-books-json.mjs)──▶ public/api/books.json  (站点托管，远程端点)
                                                  └▶ miniprogram/data/books.local.json (离线/开发兜底)
```

- **生成脚本** `scripts/gen-books-json.mjs`：用 `node --experimental-strip-types` 直接 import 同一份 `books.ts`，输出两份 JSON。已挂到 `npm run gen:books`，并接进 `npm run build`（构建前自动生成，确保端点永远最新）。
- **远程端点**：`https://lystrosaurus.github.io/api/books.json`，小程序运行时 `wx.request` 拉取。
- **同步比对**：JSON 带 `syncToken`（= `meta.generatedAt`）。小程序用 `syncToken` 与本地缓存比对——相同则不刷新，不同则更新缓存。
- **兜底链**：远程成功→写缓存；远程失败→读缓存；无缓存→用打包进小程序的 `books.local.json`。保证「断网也能读」。
- **触发时机**：`App.onLaunch` 后台静默同步；`pages/profile` 提供「立即同步」手动按钮；页面 `onShow` 重新从 globalData 取数。

> 上线前需在 **微信公众平台 → 开发 → 开发设置 → 服务器域名 → request 合法域名** 添加 `lystrosaurus.github.io`（HTTPS 强制、域名白名单是平台硬约束；开发期可在 DevTools 勾选「不校验合法域名」）。

## 4. 小程序架构与平台约束

### 4.1 目录结构（已落地）

```
miniprogram/
├── app.js / app.json / app.wxss        全局入口、页面与 tabBar、暗色主题
├── project.config.json / sitemap.json  工程配置（appid 用 touristappid 可直接预览）
├── utils/
│   ├── request.js   远程拉取 + 缓存 + 兜底（含 syncToken 比对）
│   ├── storage.js   设置/书架/进度/书签 本地存储封装
│   └── format.js    配色 + mdToNodes（**加粗**/`代码` → rich-text nodes）
├── components/book-card/                复用书籍卡片
├── data/books.local.json                离线兜底数据
└── pages/
    ├── books/        书库列表（分类/状态/搜索）
    ├── book-detail/  书籍详情
    ├── reader/       阅读界面（核心能力）
    ├── shelf/        我的书架
    └── profile/      我的/设置/同步
```

### 4.2 平台约束应对

| 约束 | 处理 |
| --- | --- |
| 双线程、无 DOM | 用 WXML 数据绑定 + `setData`；结构化文本经 `rich-text` 的 nodes 渲染（无 v-html） |
| HTTPS 强制 + 域名白名单 | 仅请求 `lystrosaurus.github.io`；开发期 `urlCheck:false` |
| 主包 ≤ 2MB（分包 ≤ 20MB） | 当前主包极小（数据本地 21 本仅 ~80KB，UI 纯原生）；如后续加全文章节，按分类拆 **subpackage** |
| `setData` 跨桥开销 | 阅读进度保存**节流 400ms**；字号/主题变更批量 `setData`；不在 `onScroll` 中回写 `scroll-top` |
| 隐私合规 | 阅读/书架数据纯本地（不涉及用户信息上报），符合最小化采集 |

## 5. 四大模块详细设计

### 5.1 书籍列表（`pages/books`）
- 顶部统计：书目总数 / 已榨取 / 待榨取。
- 搜索框：书名/作者/简介实时过滤。
- 分类 Chips（8 类横向滚动）+ 状态 Chips（全部/已榨取/待榨取）。
- 双列网格渲染 `book-card`；点击 → 详情页。
- 下拉刷新触发远程同步。

### 5.2 书籍详情（`pages/book-detail`）
- 头部：书名、作者·年份·分类、榨取徽标。
- 内容分段：内容简介 → 核心命题（引用块）→ 知识点（按基础/进阶/心法分组，分级色标）→ 可行动洞察 → 金句。
- 关联书目：复用 `book-card` 回链详情。
- 底部操作栏：「加入/移出书架」+「开始阅读」。
- `onShareAppMessage`：支持微信会话/群分享，路径带 `id` 便于回流。

### 5.3 阅读界面（`pages/reader`）—— 核心能力
把一本书的萃取内容**扁平化为有序「块」数组**：
`摘要块 → 核心命题块 → 各知识点块(带分级色) → 可行动块 → 金句块`。
每个块有稳定 `key`，作为进度与书签的定位锚。

**(a) 字体大小调整**
- 字号取自全局设置 `settings.fontSize`（默认 17px，区间 14–24）。
- 底部栏 `A− / A＋` 调整并即时写回 `storage.saveSettings`，全局持久化；正文 `font-size/line-height` 通过行内样式绑定。

**(b) 阅读进度记忆**
- `onScroll` 节流（400ms）计算 `percent = scrollTop / (scrollHeight - 视口高)`，连同 `scrollTop` 存入 `progress[bookId]`。
- 再次进入时，`onReady` 读取保存的 `scrollTop` 还原滚动位置（用 `scroll-view` 的 `scroll-top` 绑定，避免回写抖动）。
- 书架页据此显示「已读 X%」。

**(c) 书签功能**
- 每块右侧 ★ 按钮 `toggleBookmark(key, title)`，存于 `bookmarks[bookId]`。
- 底部栏 ★ 打开书签面板，列出该书全部书签，点击 `scroll-into-view="block-{index}"` 跳转。

- 额外：暗/浅主题切换（护眼）。

### 5.4 个人书架（`pages/shelf`）
- 列表展示收藏的书（`storage` 中的 id 顺序），每项带分类色、阅读进度条、最近阅读时间。
- 点击条目 → `reader` 续读；✕ 移出书架。
- 空态引导去书库。

### 5.5 我的/设置（`pages/profile`）
- 默认字号、阅读主题（暗/浅）。
- 数据同步区：显示书目数、最近同步时间、数据来源（remote/cache/local）、「立即同步」按钮、清除本地缓存。

## 6. 与站点「阅读体验一致性」的保证

1. **同一份数据**：小程序不另建数据库，全部来自 `books.ts` 生成的 JSON。
2. **同一套视觉语言**：分类/分级配色 hex 与站点 `CATEGORY_ACCENTS` / `LEVEL_COLORS` 完全一致；暗色科技风（`#0a0a0a` 底 + 青色 `#00fff2` 强调）沿用站点设计系统。
3. **同一套信息层级**：详情页分块顺序与站点 `[slug].astro` 一一对应。
4. **联动态一致**：`relatedBookIds` / `bookIds` 在小程序内同样可点击互链。

## 7. 后续可扩展

- **全文阅读**：在 `Book` 增加可选 `chapters: { title, paragraphs[] }[]` 字段，`reader` 检测到 `chapters` 即切换为章节全文模式（块粒度不变，兼容现有进度/书签）。这是「个人阅读书籍」最自然的下一步。
- **Skyline 渲染引擎**：列表/阅读流可迁移 Skyline，获得更高滚动性能与动画表现（本项目已用原生组件，迁移成本低）。
- **订阅消息**：读完一本书后触发「读书提醒」订阅消息（替代旧模板消息）。
- **subpackage 拆分**：若书籍正文入库导致包体增大，把 `reader`/详情按分类拆子包，守住主包 < 2MB。
- **跨书复盘页**：复用 `syntheses` 数据，新增 `pages/syntheses` 与书库并列。
